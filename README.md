# Seçil & Uğur — düğün sitesi

A Turkish wedding website with a same-origin serverless RSVP API.

- **Web and API:** Next.js App Router on Vercel
- **Database:** Neon Postgres through Drizzle ORM
- **Form:** React Hook Form and Zod
- **Tests:** Vitest plus the Chrome verification script
- **Workspace:** pnpm

## Project structure

```
apps/web/
├── migrations/                  Postgres migrations
├── public/artwork/              Wedding artwork and generated derivatives
├── src/app/                     Pages plus /health and /v1/rsvp routes
├── src/components/rsvp/         RSVP form
├── src/config/site.ts           Wedding information and Turkish copy
├── src/lib/rsvp-client.ts       Same-origin browser client
└── src/server/                  Environment, database, validation and handlers
tools/verify.mjs                 Browser layout and optional live RSVP checks
```

The public page is statically generated by Next.js. The RSVP route handlers run
as Vercel Node.js Functions in the same deployment, so the browser does not need
a separate API hostname or CORS configuration.

## Development

Requires Node.js 22+ and pnpm 11+.

```bash
pnpm install
cp apps/web/.env.example apps/web/.env.local
pnpm dev
```

A real `DATABASE_URL` is required to submit locally. The page and client-side
form validation still render without database credentials.

Common commands:

```bash
pnpm dev
pnpm build
pnpm test
pnpm lint
pnpm typecheck
pnpm db:generate
pnpm db:migrate
```

## Environment

Set these in `apps/web/.env.local` for development and in Vercel Project
Settings for production:

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | Yes | Neon Postgres connection string |
| `RSVP_ADMIN_TOKEN` | Yes | Bearer token for the protected CSV export; minimum 24 characters |
| `RATE_LIMIT_SECRET` | Yes | HMAC key used to hash client addresses; minimum 32 characters |
| `RSVP_MAX_GUESTS` | No | Maximum party size; defaults to 10 |

Generate the two secrets independently:

```bash
openssl rand -hex 32
openssl rand -hex 32
```

Never commit `.env.local` or paste these values into frontend code.

## Database

The Postgres schema contains:

- `rsvps`: one row per browser submission token, including the guest response,
  revision, and timestamps.
- `rsvp_rate_limits`: short-lived fixed-window counters keyed by a one-way HMAC
  fingerprint. Raw client IP addresses are never stored.

Create a migration after changing `src/server/db/schema.ts`:

```bash
pnpm db:generate
```

Apply checked-in migrations to the database configured by `DATABASE_URL`:

```bash
pnpm db:migrate
```

Migrations are tracked by Drizzle and can be run repeatedly; only unapplied
migrations execute.

## RSVP HTTP contract

Responses use `{ "ok": true, "data": ... }` or
`{ "ok": false, "error": { "code", "message" } }`.

### `GET /health`

Returns 200 only when Postgres answers a query.

### `GET /v1/rsvp/config`

Returns the public maximum guest count and no personal data.

### `POST /v1/rsvp`

Accepts `application/json` with a 16 KiB body limit:

| Field | Type | Rules |
| --- | --- | --- |
| `submissionToken` | string | Browser-generated token, 8–128 characters |
| `fullName` | string | 2–120 characters after whitespace normalization |
| `attendance` | `"yes"` or `"no"` | Required |
| `guestCount` | integer | 1–maximum when attending; stored as 0 otherwise |
| `note` | string | Optional, maximum 500 characters |
| `website` | string | Hidden honeypot; real guests leave it empty |

The first valid submission returns 201 with `status: "created"`. Reusing the
same browser token atomically updates that row and returns 200 with
`status: "updated"`. The endpoint permits 12 attempts per client-address
fingerprint in each ten-minute window.

### `GET /v1/rsvp/export.csv`

Returns all responses oldest-first as a Turkish Excel-compatible UTF-8 CSV.
Requires the admin token in the Authorization header:

```bash
curl -H "Authorization: Bearer $RSVP_ADMIN_TOKEN" \
  -o katilimlar.csv \
  https://your-project.vercel.app/v1/rsvp/export.csv
```

The token is not accepted in query parameters. Cells are quoted and values that
could be interpreted as spreadsheet formulas are neutralized.

## Vercel + Neon deployment

1. Import this repository into Vercel and set the project root to `apps/web`.
2. Add Neon from the Vercel Marketplace and connect it to the project. This
   injects `DATABASE_URL`.
3. Add `RSVP_ADMIN_TOKEN`, `RATE_LIMIT_SECRET`, and
   `RSVP_MAX_GUESTS=10` to the Production environment.
4. Pull or copy the production `DATABASE_URL` into a secure local environment
   and run `pnpm db:migrate`.
5. Deploy the default branch.
6. Confirm `/health`, submit a test RSVP, update it in the same browser, and
   download the protected CSV.
7. Remove the verification row from Neon after the checks pass.

Because the API is same-origin, moving from the Vercel domain to a custom domain
requires no RSVP client change. Update `share.siteUrl` in
`apps/web/src/config/site.ts` when the final public domain is known.

## Verification

```bash
pnpm build
node tools/verify.mjs
```

The default run starts the production Next.js server, drives local Chrome, and
checks responsive layout, motion, contrast, and form controls. To exercise a
configured Neon database too:

```bash
DATABASE_URL=... \
RSVP_ADMIN_TOKEN=... \
RATE_LIMIT_SECRET=... \
node tools/verify.mjs --live-rsvp
```

The live mode creates a uniquely named verification RSVP, updates it, and checks
that it appears in the protected CSV. Delete that row after verification.

## Editing wedding content

- Wedding details and Turkish copy: `apps/web/src/config/site.ts`
- Colors, typography, and spacing: `apps/web/src/app/globals.css`
- Venue artwork: `apps/web/public/artwork/`
- RSVP behavior: `apps/web/src/components/rsvp/RsvpForm.tsx` and
  `apps/web/src/server/`

The browser token prevents accidental duplicates only. It is not guest
authentication: a different browser or cleared browser storage creates a new
row.
